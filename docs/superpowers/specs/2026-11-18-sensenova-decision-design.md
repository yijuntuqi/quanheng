# 权衡：SenseNova 与简洁工作区设计

## 目标

保留透明、可编辑的多因素决策工具，接入 SenseNova 生成决策草稿、提示遗漏和解释本地计算结果。页面保持单页、低干扰，不引入登录、跨设备同步或云端历史记录。

## 已确认约束

- API Key 只能由服务端从 `SENSENOVA_API_KEY` 读取，不写入前端、示例配置或仓库。
- 使用 `https://token.sensenova.cn/v1/chat/completions`，默认模型 `sensenova-6.8-flash-lite`，允许通过环境变量覆盖。
- SenseNova 使用 `response_format: { type: "json_object" }`；响应由服务端解析并通过 Zod 校验。
- 所有 AI 操作由用户手动触发，不在输入停顿后自动调用。
- 本地 `decisionEngine.ts` 始终是排名、优势代价、翻盘条件和压力测试的唯一计算来源。
- AI 内容只是可编辑草稿和讨论提示，不作为已核实事实或现实概率。
- 当前决策仍只保存到浏览器 `localStorage`。
- 本次以本地开发测试为目标，不修改 Netlify 部署。
- 项目当前没有测试文件，不新增测试或测试脚手架；使用现有类型检查、Lint、构建和实际页面操作验证。

## AI 能力

### 决策草稿

用户输入问题并点击生成。AI 返回 2–4 个选项、3–6 个因素、权重、评分，以及：

- `watchouts`：遗漏代价、关键假设、待核实事实。
- `followUpQuestions`：帮助用户澄清偏好的追问。

生成前内容可撤销；失败不得覆盖当前决策。

### 结果解读

用户在结果区点击“AI 解读”。服务端接收当前决策和本地分析结果，返回简短结论、主要取舍和追问。任何后续编辑都会使旧解读失效并隐藏。

## 页面

- 压缩宣传内容和垂直留白，让问题输入与决策表成为视觉主体。
- 保留选项、因素、评分、结果、底线和导出。
- 压力测试与计算方法作为次级内容，不抢占首屏。
- AI 提醒与解读按需展示，不增加独立页面。
- 使用 `src/sections/` 拆分问题区、编辑区和结果区，`Home.tsx` 负责状态与 API 编排。

## 清理

删除未使用的 `db/`、`contracts/`、`api/queries/`、`drizzle.config.ts` 和 Drizzle/MySQL 依赖。保留 Hono/tRPC 作为本地 AI 服务端，不批量删除未使用的 UI 组件。

## 完成标准

- `npm run check`、`npm run lint`、`npm run build` 通过。
- 本地服务可启动，手动决策、编辑、保存和导出不受 AI 配置影响。
- 未配置 Key 时 AI 给出可理解错误，不丢失当前编辑。
- 用户配置新 Key 后，可手动生成草稿和请求结果解读。
